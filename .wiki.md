# Project Summary

Atlasphere est une plateforme communautaire consacrée à la découverte, au financement et à la gouvernance de projets liés à Pi Network. Les membres peuvent suivre des projets, contribuer en Pi, voter, participer à des quêtes et échanger. La plateforme propose aussi des profils, des avis, des notifications, des outils de réputation et une assistance IA.

Les paiements Pi suivent un parcours User-to-App : authentification du Pioneer, approbation dans le wallet, puis finalisation et vérification côté serveur. `PI_API_KEY` est réservée au backend et doit être fournie par un gestionnaire de secrets. `OIDC_CLIENT_ID` concerne uniquement Atoms/OIDC.

Le backend prend en charge les déploiements locaux et les environnements Lambda à arborescence aplatie grâce à des paquets de compatibilité d’import. La route publique `GET /api/v1/entities/projects/all` conserve le contrat `{items, total, skip, limit}`.

Les pages Privacy et Terms sont disponibles en dix langues. Les ressources marketing comprennent une feuille de route en Markdown et PDF, ainsi qu’une campagne de 17 visuels.

# Project Module Description

- **Projets et contributions** : découverte, suivi et financement de projets ; les contributions sont créditées après confirmation du paiement.
- **Gouvernance** : propositions et votes, dont le vote quadratique.
- **Paiements Pi** : parcours User-to-App, reprise des paiements inachevés, callbacks et finalisation idempotente côté backend.
- **Authentification** : connexion Pi Network dans Pi Browser et callback `/auth/callback`.
- **Profils et communauté** : profils, commentaires, messagerie et notifications.
- **Avis des Pioneers** : notes, commentaires et statistiques sur `/feedback`.
- **Quêtes et réputation** : progression, badges, parrainage et suivi de réputation.
- **Fonctionnalités d’écosystème** : assistant IA, API d’écosystème, NFT, prédictions, carte, suivi de projets et analyses.
- **API projets** : liste publique des projets ; les opérations CRUD restent authentifiées.
- **Tests et administration** : paiements testables sur `/payment-test` ; administration selon les noms définis dans `VITE_ADMIN_USERNAMES`.
- **Documentation et marketing** : guides développeur, documentation API, feuille de route et ressources visuelles.
- **Conformité** : pages juridiques localisées en dix langues.

# Usage

## Configuration

Fournir `PI_API_KEY` au backend via un gestionnaire de secrets ; ne pas exposer cette clé dans le frontend ni dans le dépôt. L’authentification Pi utilise `Pi.authenticate(...)` dans Pi Browser. `OIDC_CLIENT_ID` concerne uniquement Atoms/OIDC.

Configurer les variables frontend nécessaires, notamment `VITE_ADMIN_USERNAMES` pour les comptes administrateurs Pi. Plusieurs noms peuvent être séparés par des virgules.

Utiliser Mainnet pour les paiements réels et Testnet/Sandbox pour les essais ; la configuration réseau et la clé serveur doivent correspondre. La clé publique de validation se trouve dans `app/frontend/public/validation-key.txt`.

## Installer les dépendances

```bash
cd app/frontend
pnpm install
```

```bash
pip install -r requirements.txt
```

## Démarrer, migrer et vérifier

Depuis la racine du projet :

```bash
bash app/start_app_v2.sh
```

Appliquer les migrations lorsque la base de données est disponible :

```bash
cd app/backend
alembic upgrade head
```

Vérifier et compiler le frontend :

```bash
cd app/frontend
pnpm run lint
pnpm run build
```

Pour valider le backend après un déploiement, vérifier l’import des modules et la route publique `GET /api/v1/entities/projects/all`, avec sa réponse `{items, total, skip, limit}`. Les paiements se testent sur `/payment-test` et les avis des Pioneers sur `/feedback`. Effectuer les essais Pi dans Pi Browser avec une application enregistrée et un domaine validé dans le Developer Portal.
