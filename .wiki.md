# Project Summary

Atlasphere est une plateforme communautaire dédiée à la découverte, au financement et à la gouvernance de projets liés à Pi Network. Les membres peuvent suivre des projets, contribuer en Pi, voter sur des propositions, participer à des quêtes et suivre leur activité communautaire. La plateforme comprend également des fonctionnalités d’écosystème, de réputation, de notifications et d’assistance IA.

Les paiements Pi reposent sur le flux Pi SDK v2.0 : authentification du Pioneer, création et approbation du paiement, signature dans le wallet, complétion et vérification côté serveur. Le mode Mainnet ou Testnet/Sandbox est sélectionné explicitement, et la clé API Pi reste côté backend.

# Project Module Description

- **Projets et contributions** : découverte, suivi et financement des projets ; les contributions ne sont créditées qu’après confirmation du paiement.
- **Gouvernance** : propositions, votes et vote quadratique.
- **Paiements Pi** : parcours User-to-App, reprise des paiements inachevés, callbacks de paiement et registre idempotent pour éviter les crédits en double.
- **Profils et communauté** : authentification Pi, profils, commentaires, messagerie, notifications et paramètres de notification.
- **Quêtes et réputation** : quêtes, progression, badges, parrainage et suivi de réputation.
- **Fonctionnalités d’écosystème** : assistant IA, API d’écosystème, NFT, prédictions, carte et suivi des projets, analyses.
- **Test des paiements** : `/payment-test` permet de tester les paiements et de suivre les testeurs.
- **Administration et configuration** : `/settings` et `/admin` sont soumis à la liste de noms Pi configurée dans `VITE_ADMIN_USERNAMES`.
- **Documentation et conformité** : guides développeur, documentation API, ressources marketing et pages de confidentialité et de conditions d’utilisation localisées.

# Technology Stack

- **Frontend** : React, TypeScript, Vite
- **Backend** : Python, FastAPI, Pydantic
- **Base de données** : SQLAlchemy et Alembic
- **Paiements** : Pi SDK v2.0 côté frontend et API Pi Platform côté serveur
- **Client HTTP** : HTTPX
- **Internationalisation** : traductions JSON et modules i18n
- **Gestion des dépendances** : npm/pnpm et pip

# Usage

## Configuration

Configurer `PI_API_KEY` dans l’environnement serveur. Ne jamais exposer cette clé dans le frontend.

Configurer, selon les besoins, les variables frontend, notamment `VITE_ADMIN_USERNAMES` pour les comptes administrateurs Pi. Cette liste accepte plusieurs noms séparés par des virgules. Le nom actuellement documenté comme autorisé est `portraitart`.

Choisir explicitement le réseau de paiement correspondant à l’environnement et au wallet : Mainnet pour les paiements réels, Testnet/Sandbox pour les essais. La clé serveur et le réseau doivent correspondre. Republier le frontend après toute modification de sa configuration.

## Installer les dépendances

```bash
cd app/frontend
pnpm install
```

Installer les dépendances Python depuis le répertoire backend en utilisant le fichier de dépendances adapté à l’environnement :

```bash
cd app/backend
pip install -r requirements.txt
```

## Lancer et vérifier

Démarrer le backend avec la commande de lancement définie par la configuration du projet. Appliquer les migrations quand la base de données est disponible :

```bash
cd app/backend
alembic upgrade head
```

Vérifier et compiler le frontend :

```bash
cd app/frontend
pnpm run lint
pnpm run build
```

Les principaux parcours de paiement se trouvent sur `/payment-test`. Effectuer les essais Pi dans Pi Browser avec une application enregistrée et un domaine validé dans le Developer Portal. Vérifier que le compte, le wallet, le mode réseau et la clé serveur ciblent le même réseau. Un premier essai de faible montant est recommandé.
