# Project Summary

Atlasphere est une plateforme communautaire de découverte, de financement et de gouvernance de projets liés à Pi Network. Les membres peuvent suivre des projets, contribuer en Pi, voter, accomplir des quêtes et consulter leur activité. La plateforme propose aussi des outils de réputation, des notifications et une assistance IA.

Les paiements Pi suivent un parcours User-to-App : authentification du Pioneer, approbation dans le wallet, puis finalisation et vérification côté serveur. Le réseau Mainnet ou Testnet/Sandbox dépend de l’environnement. L’adresse wallet Atlasphere est configurée dans le backend Pi : `GA2JQ5C2QXIY3DRWCOYIAHYBEJFXLYURIG3XQD7G4HUZY4EPFPGA443G`.

La clé Pi App API est fournie via le gestionnaire de secrets et injectée dans le backend sous `PI_API_KEY`. Elle ne doit pas être exposée dans le frontend, le dépôt ou le chat. Le flux actuel d’authentification Pi Network utilise `Pi.authenticate(...)` dans Pi Browser, puis le backend vérifie le jeton Pi. `OIDC_CLIENT_ID` concerne l’authentification Atoms/OIDC.

Pour la configuration Pi Sign-In dans Pi Develop, l’URI de redirection à enregistrer est `https://atlasphere.pub.atoms.world/auth/callback`. Cette adresse correspond à la route de callback présente dans Atlasphere.

La clé publique de validation Pi est publiée à `/validation-key.txt`. La page `/feedback` permet aux Pioneers de noter l’application, de publier un commentaire et de consulter les avis et statistiques associés à un paiement vérifié.

Les pages juridiques sont les fichiers publics `/terms.html` et `/privacy.html`. Les anciennes routes SPA `/terms` et `/privacy` ont été retirées.

# Project Module Description

- **Projets et contributions** : découverte, suivi et financement de projets. Les contributions sont créditées après confirmation du paiement.
- **Gouvernance** : propositions, votes et vote quadratique.
- **Paiements Pi** : parcours User-to-App, reprise des paiements inachevés, callbacks et registre idempotent. La configuration et la finalisation sont gérées côté backend.
- **Validation Pi** : publication de la clé publique à `/validation-key.txt`.
- **Authentification** : authentification Pi Network dans Pi Browser et callback `/auth/callback` pour la configuration Pi Sign-In.
- **Profils et communauté** : profils, commentaires, messagerie et notifications.
- **Avis des Pioneers** : notes, commentaires et statistiques sur `/feedback`.
- **Quêtes et réputation** : progression, badges, parrainage et suivi de réputation.
- **Fonctionnalités d’écosystème** : assistant IA, API d’écosystème, NFT, prédictions, carte, suivi de projets et analyses.
- **Tests de paiement** : `/payment-test` pour tester les paiements et suivre les testeurs.
- **Administration et configuration** : `/settings` et `/admin` dépendent des noms Pi définis dans `VITE_ADMIN_USERNAMES`.
- **Documentation et conformité** : guides développeur, documentation API, ressources marketing et pages juridiques HTML localisées.

# Usage

## Configuration

Fournir `PI_API_KEY` au backend via le gestionnaire de secrets. Ne pas exposer cette clé dans le frontend, le dépôt ou les échanges de chat.

Pour Pi Sign-In dans Pi Develop, ajouter cette URI dans **Redirect URIs**, une seule adresse par ligne :

```text
https://atlasphere.pub.atoms.world/auth/callback
```

Le flux Pi Network actuel utilise `Pi.authenticate(...)` dans Pi Browser et ne nécessite pas d’Auth Client ID Pi. `OIDC_CLIENT_ID` est réservé au flux Atoms/OIDC.

Configurer les variables frontend nécessaires, notamment `VITE_ADMIN_USERNAMES` pour les comptes administrateurs Pi. La liste accepte plusieurs noms séparés par des virgules.

Choisir le réseau de paiement adapté à l’environnement et au wallet : Mainnet pour les paiements réels, Testnet/Sandbox pour les essais. La clé serveur et le réseau doivent correspondre.

La clé publique de validation est fournie par `app/frontend/public/validation-key.txt` et publiée à `/validation-key.txt`. Les pages juridiques HTML sont accessibles à `/terms.html` et `/privacy.html`.

## Installer les dépendances

Installer les dépendances frontend :

```bash
cd app/frontend
pnpm install
```

Installer les dépendances Python :

```bash
cd app/backend
pip install -r requirements.txt
```

## Démarrer et vérifier

Depuis la racine du projet, démarrer l’application :

```bash
bash app/start_app_v2.sh
```

Pour appliquer les migrations lorsque la base de données est disponible :

```bash
cd app/backend
alembic upgrade head
```

Vérifier et compiler le frontend :

```bash
cd app/frontend
pnpm run lint
pnpm run build
```

Les parcours de paiement se testent sur `/payment-test` et les avis des Pioneers sur `/feedback`. Effectuer les essais Pi dans Pi Browser avec une application enregistrée et un domaine validé dans le Developer Portal.
