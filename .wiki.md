# Project Summary

Atlasphere est une plateforme communautaire dédiée à la découverte, au financement et à la gouvernance de projets liés à Pi Network. Les membres peuvent suivre des projets, contribuer en Pi, voter, accomplir des quêtes, échanger et consulter leur activité. La plateforme propose également des outils de réputation, des notifications et une assistance IA.

Les paiements Pi suivent un parcours User-to-App : authentification du Pioneer, approbation dans le wallet, puis finalisation et vérification côté serveur. L’authentification Pi utilise `Pi.authenticate(...)` dans Pi Browser. La clé `PI_API_KEY` doit rester côté backend et être fournie par un gestionnaire de secrets. `OIDC_CLIENT_ID` est réservé à l’authentification Atoms/OIDC.

Les pages Privacy et Terms sont proposées en dix langues. Leur menu de langues conserve les choix signalés par des drapeaux, sans lien « Accueil » ni icône de maison.

# Project Module Description

- **Projets et contributions** : découverte, suivi et financement de projets ; les contributions sont créditées après confirmation du paiement.
- **Gouvernance** : propositions et votes, dont le vote quadratique.
- **Paiements Pi** : parcours User-to-App, reprise des paiements inachevés, callbacks et finalisation idempotente côté backend.
- **Authentification** : connexion Pi Network dans Pi Browser et callback `/auth/callback`.
- **Profils et communauté** : profils, commentaires, messagerie et notifications.
- **Avis des Pioneers** : notes, commentaires et statistiques sur `/feedback`.
- **Quêtes et réputation** : progression, badges, parrainage et suivi de réputation.
- **Fonctionnalités d’écosystème** : assistant IA, API d’écosystème, NFT, prédictions, carte, suivi de projets et analyses.
- **Tests et administration** : `/payment-test` pour les paiements ; `/settings` et `/admin` selon les noms définis dans `VITE_ADMIN_USERNAMES`.
- **Documentation et conformité** : guides développeur, documentation API, ressources marketing et pages juridiques localisées.

# Usage

## Configuration

Fournir `PI_API_KEY` au backend via le gestionnaire de secrets ; ne pas exposer cette clé dans le frontend ni dans le dépôt. Le flux Pi Network utilise `Pi.authenticate(...)` dans Pi Browser. `OIDC_CLIENT_ID` concerne uniquement Atoms/OIDC.

Configurer les variables frontend nécessaires, notamment `VITE_ADMIN_USERNAMES` pour les comptes administrateurs Pi. Plusieurs noms peuvent être séparés par des virgules.

Utiliser Mainnet pour les paiements réels et Testnet/Sandbox pour les essais ; la configuration réseau et la clé serveur doivent correspondre. La clé publique de validation est fournie dans `app/frontend/public/validation-key.txt`.

## Installer les dépendances

```bash
cd app/frontend
pnpm install
```

```bash
cd app/backend
pip install -r requirements.txt
```

## Démarrer, migrer et vérifier

Depuis la racine du projet :

```bash
bash app/start_app_v2.sh
```

Appliquer les migrations lorsque la base de données est disponible :

```bash
cd app/backend
alembic upgrade head
```

Vérifier et compiler le frontend :

```bash
cd app/frontend
pnpm run lint
pnpm run build
```

Les paiements se testent sur `/payment-test` et les avis des Pioneers sur `/feedback`. Effectuer les essais Pi dans Pi Browser avec une application enregistrée et un domaine validé dans le Developer Portal.
