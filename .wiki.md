# Project Summary

Atlasphere est une plateforme de découverte, de financement et de gouvernance communautaire autour de Pi Network. Les utilisateurs peuvent consulter des projets, voter, contribuer financièrement et payer en Pi depuis Pi Browser.

Les paiements suivent le parcours Pi Network de création, approbation serveur, signature par le Pioneer, complétion et vérification serveur. Le flux a été renforcé pour les testeurs externes : Pi Browser utilise désormais le mode réel approprié, le jeton Pi peut servir de preuve d’identité lors de l’approbation et les erreurs sont affichées au lieu d’être ignorées.

Les paiements Testnet/Sandbox restent disponibles pour les essais, tandis que les paiements Mainnet nécessitent une clé serveur et un réseau correspondants.

L’accès aux fonctions d’administration dépend du nom d’utilisateur Pi Network configuré côté frontend. Le compte `portraitart` est actuellement autorisé pour `/settings` et `/admin`.

# Project Module Description

- **Paiements Pi Network**
  - Flux User-to-App en quatre étapes depuis Pi Browser.
  - Authentification Pi effectuée avant l’ouverture du wallet.
  - Approbation serveur basée sur le jeton Pi du payeur lorsque nécessaire.
  - Vérification du jeton, du payeur, du montant, du bénéficiaire, de la direction, du réseau, du paiement et du txid.
  - Délais réseau réduits afin de respecter la fenêtre d’approbation du wallet.
  - Clé `PI_API_KEY` conservée uniquement côté backend.
- **Gestion des erreurs de paiement**
  - Affichage de la cause réelle d’un échec côté frontend.
  - Enregistrement des annulations effectuées dans le wallet.
  - Réduction des échecs silencieux pendant la création, l’approbation et la complétion.
- **Registre des paiements**
  - Suivi des approbations, complétions, annulations et erreurs.
  - Enregistrement du réseau utilisé, Testnet ou Mainnet.
  - Idempotence par `payment_id` et prévention des crédits en double.
  - Historique limité au compte Atlasphere authentifié.
- **Financement de projets**
  - Crédit des projets uniquement après confirmation Pi Network.
  - Enregistrement des contributions et passage automatique au statut financé selon le budget.
- **Testeurs Pi Developer**
  - Page `/payment-test` avec montants de test de 0,1, 0,5 et 1 Pi.
  - Compteur des testeurs distincts, progression vers cinq utilisateurs et liste anonymisée.
  - Historique personnel des paiements.
- **Administration et configuration**
  - Route `/settings` réservée aux administrateurs Pi configurés.
  - Tableau de bord `/admin` protégé par la même vérification.
  - Liste administrateur définie par `VITE_ADMIN_USERNAMES`, avec comparaison insensible à la casse.
  - Compte actuellement autorisé : `portraitart`.
- **Configuration réseau**
  - Consultation de la configuration Testnet/Mainnet et de la checklist de déploiement.
  - Le mode Pi est sélectionné selon le contexte Pi Browser et la configuration réseau attendue.
  - La clé serveur et le réseau du wallet doivent correspondre.
- **Conditions de test**
  - Utilisation de Pi Browser.
  - Application enregistrée dans le Developer Portal avec domaine validé.
  - Clé Pi de l’application configurée côté serveur.
  - Paiement initial recommandé de 0,1 Pi.
- **Interface multilingue**
  - Libellés de paiement en arabe, anglais, espagnol, français, portugais, russe et chinois.

# Technology Stack

- **Frontend** : React, TypeScript, Vite, Tailwind CSS
- **Backend** : Python, FastAPI, Pydantic
- **Base de données** : SQLAlchemy asynchrone, Alembic
- **Paiements** : Pi Network SDK côté frontend et Pi Platform API côté serveur
- **Réseaux Pi** : Testnet/Sandbox pour les essais, Mainnet pour les paiements réels
- **Client HTTP** : HTTPX
- **Internationalisation** : moteur i18n interne multilingue
- **Configuration** : variables d’environnement Vite
- **Validation** : compilation Python, lint frontend et build de production

# Usage

## Variables d’environnement

Configurer côté serveur :

```bash
PI_API_KEY=<clé serveur Pi Network>
```

Configurer côté frontend dans `app/frontend/.env` :

```bash
VITE_APP_TITLE=Atlasphere
VITE_APP_DESCRIPTION=Gouvernance décentralisée pour Pi Network. Votez, financez et construisez l'avenir de votre communauté.
VITE_APP_LOGO_URL=/assets/logo-atlasphere-transparent.png
VITE_ADMIN_USERNAMES=portraitart
```

`VITE_ADMIN_USERNAMES` accepte plusieurs noms séparés par des virgules et ne doit contenir que des identifiants Pi autorisés. La clé `PI_API_KEY` ne doit jamais être exposée au frontend.

La clé serveur Pi et le réseau utilisé par le wallet doivent être cohérents. Republier l’application après toute modification de configuration frontend.

## Routes principales

- `/` : accueil de la plateforme.
- `/payment-test` : tests de paiement Pi et suivi des testeurs.
- `/settings` : configuration réseau et checklist de déploiement pour les administrateurs.
- `/admin` : tableau de bord administrateur.
- `/marketing-download` : pack marketing.
- `/api/v1/pi/validation-key` : clé de validation Pi.

## Conditions de test

- Ouvrir l’application dans Pi Browser.
- Enregistrer l’application dans le Developer Portal et valider son domaine.
- Se connecter avec Pi avant de lancer le wallet.
- Utiliser de préférence le montant de 0,1 Pi pour le premier test.
- Fermer puis rouvrir Pi Browser après une nouvelle publication.
- Les Test-Pi n’ont aucune valeur réelle, mais reproduisent le parcours technique de production.
- Pour l’administration, utiliser un compte dont le nom figure dans `VITE_ADMIN_USERNAMES`.
- En cas d’échec, relever le message affiché à l’écran et l’état enregistré du paiement.

## Backend

Installer les dépendances selon la configuration existante du projet, puis lancer le backend avec la commande habituelle de l’application.

Vérifier la syntaxe des modules modifiés :

```bash
cd app/backend
python -m py_compile \
  routers/pi_pay.py \
  dependencies/auth.py \
  services/pi_platform.py \
  services/pi_payment_ledger.py
```

Appliquer les migrations avec Alembic lorsque l’environnement de base de données est disponible :

```bash
cd app/backend
alembic upgrade head
```

## Frontend

```bash
cd app/frontend
pnpm install
pnpm run lint
pnpm run build
```

Les paiements réels doivent être testés dans Pi Browser avec des comptes Pioneer distincts. Les tests Testnet/Sandbox valident l’intégration technique, mais ne remplacent pas les paiements Mainnet requis pour l’ouverture publique.
