# Project Summary

Atlasphere est une plateforme communautaire consacrée aux projets de l’écosystème Pi Network. Elle permet aux Pioneers de découvrir et suivre des projets, de contribuer en Pi, de participer à la gouvernance et d’échanger au sein de la communauté. Des outils de quêtes, de réputation, d’avis et d’assistance IA complètent l’expérience.

Les paiements utilisent le parcours User-to-App : authentification du Pioneer, approbation dans le wallet, puis finalisation et vérification côté serveur. L’authentification Pi se fait dans Pi Browser avec `Pi.authenticate(...)`. `PI_API_KEY` doit rester côté backend et être fournie par un gestionnaire de secrets ; `OIDC_CLIENT_ID` est réservé à Atoms/OIDC.

Le projet comprend des pages Privacy et Terms en dix langues, ainsi que des ressources marketing, dont une feuille de route et un pack de visuels.

# Project Module Description

- **Projets et contributions** : découverte, suivi et financement de projets ; données simulées disponibles en JSON et via un service backend.
- **Gouvernance** : propositions et votes, dont le vote quadratique.
- **Paiements Pi** : flux User-to-App, reprise des paiements inachevés, callbacks et finalisation idempotente côté serveur.
- **Authentification** : connexion Pi Network dans Pi Browser et callback `/auth/callback`.
- **Accueil** : page d’entrée de la plateforme dans `Index.tsx`.
- **Communauté** : profils, commentaires, messagerie et notifications.
- **Avis des Pioneers** : notes, commentaires et statistiques sur `/feedback`.
- **Quêtes et réputation** : progression, badges, parrainage et suivi de réputation.
- **Fonctionnalités d’écosystème** : assistant IA, API d’écosystème, NFT, prédictions, carte, suivi de projets et analyses.
- **Tests et administration** : paiements testables sur `/payment-test` ; administration configurée via `VITE_ADMIN_USERNAMES`.
- **Documentation et conformité** : guides développeur, documentation API, ressources marketing et pages juridiques localisées.

# Usage

## Configuration

Fournir `PI_API_KEY` au backend via un gestionnaire de secrets ; ne pas l’exposer dans le frontend ni dans le dépôt. Le flux Pi Network utilise `Pi.authenticate(...)` dans Pi Browser. `OIDC_CLIENT_ID` concerne uniquement Atoms/OIDC.

Configurer les variables frontend nécessaires, notamment `VITE_ADMIN_USERNAMES` pour les comptes administrateurs Pi. Plusieurs noms peuvent être séparés par des virgules.

Utiliser Mainnet pour les paiements réels et Testnet/Sandbox pour les essais ; la configuration réseau et la clé serveur doivent correspondre. La clé publique de validation se trouve dans `app/frontend/public/validation-key.txt`.

## Installer les dépendances

```bash
cd app/frontend
pnpm install
```

```bash
pip install -r requirements.txt
```

## Démarrer, migrer et vérifier

Depuis la racine du projet :

```bash
bash app/start_app_v2.sh
```

Appliquer les migrations lorsque la base de données est disponible :

```bash
cd app/backend
alembic upgrade head
```

Vérifier et compiler le frontend :

```bash
cd app/frontend
pnpm run lint
pnpm run build
```

Les paiements se testent sur `/payment-test` et les avis des Pioneers sur `/feedback`. Effectuer les essais Pi dans Pi Browser avec une application enregistrée et un domaine validé dans le Developer Portal.
